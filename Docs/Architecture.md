# Foundation architecture
One runtime module; editor Python isolated under Content/Python and editor-only plugins.
First-person ACharacter uses conventional CharacterMovement replication and Enhanced Input. Transient mapping context avoids fabricating input assets.
Interaction component sends a no-target RPC through its owning pawn; server traces its own pawn eye position and control rotation, maximum 300 cm, visibility blocking, 200 ms cadence. Engine RPC ownership applies. Replicated switch count supports initial late-join state.
Test target is a collision reference only; combat is not implemented. No arbitrary damage API.
UMG dependency reserved for presentation; current prompt is world text. No GAS/Iris/World Partition.
G1 will introduce stable-ID mission/outpost records and host-owned versioned saves with backup-safe atomic replacement. Inventory, recovery packs and AI remain later work.

G1: Campaign.h/.cpp add a stable-ID mission record on replicated GameState, authoritative ordered checkpoint actions, authored outpost visibility/spawn changes, and host-only persistent evidence banking. CampaignTests.cpp covers invariants, duplicate action rejection, authority prerequisites, migration and actual filesystem backup recovery. See G1.md for save envelope, atomic replacement and diagnostic limits. No inventory combat AI or recovery-pack implementation is implied.

G2: Combat.h/.cpp add replicated health/life/armor, owned weapon slots and bounded per-weapon ammunition. Server owns hitscan, ammo spending, reload deadlines, gadget charges and revive completion. Public health/equipped ID replicate to relevant peers; detailed combat inventory and definition references replicate owner-only. Prototype static meshes and query boxes are presentation/hit-region stand-ins. CombatDiagnostics.cpp is opt-in packaged test setup; ordinary sessions do not teleport or auto-fire. The G2 map overrides the pawn via CombatGameMode and retains G1 mission/save behavior. See G2.md for exact boundaries; no recovery-pack or AI claim.

G3 supersedes the earlier absence of squads/recovery packs: Coop.h/.cpp add durable transaction-before-publish loot claims, owner-only field inventory, uniquely identified recovery packs and authoritative banking. Failed durable writes leave inventory and record unchanged; disconnected guest items retry as pending packs. GameState schema 2 replicates persistent world records to late joiners. A versioned migration test reads an actual schema 1 binary fixture. Host equipment remains session state; guest accounts are not permanent.
Squad.h/.cpp uses server AI Perception, navigation, actual native transient Behavior Trees and EQS cover queries. A coordinator shares timestamped last sightings and exclusive expiring cover reservations. Sight updates require line of sight; eight-second stale memory is discarded. Rifleman/support/marksman have distinct scoring and firing behavior. Runtime dependencies are AIModule, NavigationSystem and GameplayTasks. Editor Python remains editor-only. No native transient query/tree is represented as a saved binary asset.
Oblique hitscan muzzle traces now extend two centimeters through the eye-hit surface to avoid floating-point endpoint misses; the barrel obstruction checks still run first. Diagnostics are opt-in local test flags, never client-supplied damage. Server owns faction friendly-fire rejection, shot cadence/ownership, damage, inventory, claims, mission and outpost state.
